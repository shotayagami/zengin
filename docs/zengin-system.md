# 全銀システム(全国銀行データ通信システム) 調査

調査日: 2026-11-21

「中央に全銀ネットを置く」構成を作るための調査。実際の全銀システムの構成と、公開資料で分かる範囲をまとめる。
全銀協標準通信プロトコル(企業と銀行の間)とは別の仕組みなので、混同しないこと。

## 1. 全銀ネットと全銀システム

- **全銀システム**: 国内の為替取引(他行宛の振込など)を、銀行間でオンライン・リアルタイムに処理するセントラルシステム。1973年4月に稼働した。
- **全銀ネット**(一般社団法人全国銀行資金決済ネットワーク): 全銀システムを運営する資金清算機関。資金決済法にもとづく免許制の法人で、2010年に設立された。
- 参加者(加盟銀行)は、銀行のほか信用金庫、信用組合、労働金庫、農協などで、2014年12月末に1,340行。ほぼすべての預金取扱金融機関が参加している。
- 規模は、2025年12月で1営業日あたり約843万件・約17.5兆円。
- センターは東京と大阪の2か所にあり、回線も多重化されている。

出典: 全銀協「全国銀行データ通信システム」ページ、全銀ネット資料(金融庁、平成27年2月5日)。

## 2. 構成

```
企業 ─(全銀協標準通信プロトコル等)→ 仕向銀行 ─ 中継コンピュータ(RC) ─┐
                                                                  ├─ 全銀センター(ホスト) ─┐
企業 ←─────────────────────────── 被仕向銀行 ─ 中継コンピュータ(RC) ─┘                       │
                                                                    日本銀行(日銀ネット)で決済 ←┘
```

- 全銀システムは、全銀センターの**ホストコンピュータ**、各加盟銀行にある**中継コンピュータ(RC)**、その間の**回線**で構成される。
- RC は、加盟銀行の自行システムと全銀センターの間を中継する。伝送制御手順と電文形式の変換などを行う。
- 仕向銀行(顧客から振込の依頼を受けた銀行)は、全銀システムに為替通知を送る。
  全銀システムは、それを被仕向銀行(受取人の銀行)が受け取れる形式に変換して送る。
- 為替通知は、仕向銀行と被仕向銀行の間でやり取りされる、内国為替取引の通知。

## 3. 為替通知の送り方

| 方式 | 内容 |
|---|---|
| テレ為替 | 1件ずつオンライン・リアルタイムで送る。受取人の口座に即時に着金する |
| MTデータ伝送 | 複数の為替通知を一括して送受信する(ファイル転送方式)。第3次システム(1987年)で開始 |
| 新ファイル転送 | MTデータ伝送の後継。第6次システム(2011年)で導入。一括で大量のデータを送る |

電文の形式は2種類ある。

- **固定長電文**: 項目ごとに長さが決まっている。EDI情報欄は20桁。
- **XML電文**: ISO 20022 に準拠。可変長で、EDI情報欄(140桁)を繰り返し使える。
  全銀システムが、仕向銀行と被仕向銀行の電文形式の違いを吸収して変換する(2015年時点では、XML電文を採用している加盟銀行はなかった)。

## 4. 資金決済の仕組み

- 銀行間の債権債務(立替払い分)は、全銀ネットが清算し、日本銀行の当座預金口座を使って決済する。
  - **1億円以上の取引**(大口内為取引)は、取引ごとに日銀ネットへ転送し、即時に決済する(第6次システム以降)。
  - **1億円未満の取引**は、各行の受取額と支払額の差額をまとめて、毎日決済する(2015年時点で午後4時15分)。
- 決済リスクの対策が3つある。
  - **仕向超過額管理制度**: 仕向超過額(支払額 − 受取額)が、各行が申告した限度額を超えないように、システムで管理する。
  - **担保管理制度**: 限度額に見合う担保を、各行が全銀ネットに差し入れる。
  - **流動性供給制度**: 決済できない行が出たとき、全銀ネットが契約済みの銀行から資金の供給を受けて、当日の決済を完了させる。
- 全銀ネットがセントラルカウンターパーティ(CCP)として、各行の債権債務の相手方になる(2001年の新内国為替制度から)。

## 5. 稼働時間と世代

- 稼働時間は、2018年10月9日のモアタイムシステムの稼働で、24時間365日になった。
  - 2015年の資料では、8:30〜15:30が現行の稼働時間帯で、全加盟銀行の接続が義務付けられていた。
- 第6次システム(2011年)で、回線がIP-VPN網になり、TCP/IPが採用された。
- 回線の変遷: 専用回線 → 自営パケット網(第4次、1995年) → フレームリレー網(第5次、2003年。回線データ暗号化とEDI欄の追加) → IP-VPN網(第6次、2011年)。
- 第7次システムは2019年11月に稼働した。第6次の機能と構成を継承し、収容能力・処理能力の増強とサイバーセキュリティ対策を強化した。
- 2026年3月に、全銀ネットが全面刷新の構想を公表している(稼働目標は2030年。検索結果で確認したのみで、一次資料は未確認)。

## 6. 公開されていないこと

全銀システムと加盟銀行の間の電文仕様(項目定義、通信手順の詳細)は、今回の調査では公開資料に見つからなかった。
このため、中央を実装する場合の為替通知のフォーマットと手順は、公開されている概念(仕向/被仕向、為替通知、仕向超過額管理、清算)を参考に、このプロジェクトで独自に設計することになる。
実際のシステムとの互換性は持たない。

## 7. 模擬システムで再現する要素の候補

| 要素 | 本物 | 模擬の案 |
|---|---|---|
| 全銀センター | 東京・大阪の二重化ホスト | 単一のサーバ。二重化はしない |
| 中継コンピュータ | 各行にある変換装置 | 各銀行ノードが兼ねる |
| 為替通知の授受 | テレ為替、MTデータ伝送、新ファイル転送 | ファイル転送(MTデータ伝送に相当)を、全銀協標準通信プロトコルで行う |
| 電文形式 | 固定長、XML(ISO 20022) | 固定長のみ。独自のレコードを設計する |
| 振込の流れ | 仕向銀行 → 全銀システム → 被仕向銀行 | 同じ |
| 仕向超過額管理 | 限度額を超える為替を拒否 | 銀行ごとの限度額を設定し、超えたら拒否する |
| 資金決済 | 日銀の当座預金で決済 | 銀行ごとの差引残高を集計し、日次で清算の一覧を出す |
| 大口内為取引 | 1億円以上は取引ごとに即時決済 | 同じ閾値で、取引ごとの決済として記録する |
| 担保、流動性供給 | 全銀ネットが管理 | 再現しない |
| 稼働時間 | 24時間365日 | 常時稼働 |
| 振込手数料(仕向銀行 → 全銀ネット) | 1件ごとの料金 | 再現しない |
