作業メモ。仕様書の読みを自分の言葉でまとめたもので、仕様書の代わりにはならない。実装の判断は `spec-protocol.md` にある。

一次資料: 全銀協の仕様書 (`scripts/fetch-refs.sh` で `ref/jba_protocol.pdf` に取得できる。リポジトリには含めない)
(全銀協標準通信プロトコル TCP/IP手順・広域IP網、平成29年5月、全141ページ)
入手元: https://www.zenginkyo.or.jp/fileadmin/res/abstract/efforts/system/jba_protocol.pdf
下の「章/頁」は仕様書の章番号とページ番号。

## 1. 位置づけ

| 名称 | 制定 | 回線 | 状況 |
|---|---|---|---|
| ベーシック手順 | 1983 | PSTN/ISDN | 2023年末サポート終了 |
| TCP/IP手順 | 1997 | PSTN | 同上 |
| **TCP/IP手順・広域IP網** | 2017-05 | IP網(インターネット、IP-VPN) | 現行。実装対象はこれ |

- 広域IP網版は旧TCP/IP手順の電文シーケンスと制御手順を踏襲している。違いは、暗号化接続を新設して通信路の暗号化を実装側に任せた点。
- データ電文は全銀協の磁気テープ・フォーマット(総合振込、給与振込など。固定長120バイト)をそのまま使う。レコード定義は別冊「PC用ベーシック手順 適用業務およびレコード・フォーマット」にある。
  https://www.zenginkyo.or.jp/fileadmin/res/abstract/efforts/system/jba_protocol_pc.pdf

## 2. レイヤ構成 (第I〜IV章)

```
電文制御 (VI)       開局/閉局/開始/終了/再送。ファイル伝送
フォーマット (VII)   TTC + 制御電文(64B固定) + データ電文
サブレイヤ (V, VIII) 論理ACK、メッセージ=ストリーム変換
暗号化接続 (IV)     方式は当事者間で決める。仕様は規定しない
TCP/IP (III)        ポート5020、IPv4/IPv6
```

- TCP: 要求側は相手ポート 5020 に接続し、応答側は 5020 で待ち受ける。当事者間の合意で変更してもよい。
  ポート 5020 は産業別コード 5020 と偶然同じ番号で、関連はない。
- 切断: 正常終了時は接続を要求した側が解放する。障害時はどちらからでも即解放できる。
- 暗号化: 例は SSL/TLS、L2TP/IPsec、IPsec、IP-VPN。
  暗号方式は CRYPTREC の電子政府推奨暗号リストに従う。例は AES、SHA-2、RSA 2048bit以上。
  認証は、リモートアクセスならユーザ認証、サイト間接続なら機器認証(事前共有鍵、証明書、接続元IP)。
- 実装する側は、ベンダー製品を見ると TLS 方式を採るものが多い。

## 3. サブレイヤ (第V章・第VIII章)

サブレイヤヘッダ(SH)は **8バイト固定**。

| offset | 長さ | 内容 |
|---|---|---|
| 0 | 2 | メッセージ長 (バイナリ、SH込み) |
| 2 | 4bit | 版番号 = 0001 |
| 2 | 4bit | 識別子 0000=情報メッセージ(テキスト) / 0001=論理ACK |
| 3 | 4bit | AF (オプション仕様): 0=論理ACK要求 / 1=不要 |
| 3 | 4bit | MN (オプション仕様): 連続受信回数 0〜15 |
| 4 | 4 | 予備 (0x00) |

- 基本仕様の予備は5バイトで、1メッセージごとに論理ACKを返す。オプション(第VIII章)は byte3 を AF/MN に使い、予備は4バイトになる。
- 1情報メッセージ = 1テキスト。分割や連結はしない。
- 情報メッセージの長さは8以上、論理ACKの長さは8ちょうど。違反、バージョン異常、タイムアウトを検知したら TCP を強制解放する。
- 無通信監視タイマは原則30秒。送受信が完了するたびにリセットする。
- オプションの高速化(連続送信)は次の通り。
  - MN は開局要求のSHと、その論理ACKのSHで交換する。
  - 制御電文には必ず論理ACKを要求する。
  - 相手のMNが0なら、全メッセージで論理ACKを要求する(基本仕様と同じ動作)。
  - 実装の最小構成は MN=0 で、基本仕様と同じ動作になる。

## 4. 電文制御 (第VI章)

- 役割は2つある。TCP要求側が一次局(クライアント)、受諾側が二次局(サーバ)。
- モードは2つある。連絡モード(0)はTCP要求側が送信し、照会モード(1)はTCP要求側が受信する。
- シーケンスは次の通り。
  `開局要求/回答 → 開始要求/回答 → データ電文(複数) → 終了要求/回答 → 閉局要求/回答 → TCP解放`
- 開始回答で処理結果 NG(17=ファイルなし)が返った場合は、閉局へ進む。
- 再送要求電文は、From=01・To=全ビットオンなら全ファイル再送、それ以外はテキスト番号の範囲指定になる。
  47〜49頁のフローにテキスト単位の再送(#2のみ、#3のみ)がある。本文(§VI 1(6))の「ファイル単位」と食い違う。
- 再送は、同一接続内(終了要求のあとに受信側が再送要求を返す)と、新しい接続(開始要求の代わりに再送要求を返す)の2通りがある。
- 破棄はファイル単位で、終了要求/回答と閉局要求/回答が正常でなければ、受信したファイルを破棄する。
- モード変更要求/回答(04/05)で、連絡と照会を同一接続内で切り替えられる。
- 詳細は第VI章の状態遷移表(40〜43頁)とシーケンスフロー(44〜62頁)を参照。`spec-protocol.md` §4 に整理してある。
- 製品(日立)の製品マニュアルは `H0313900.PDF` (https://itpfdoc.hitachi.co.jp/manuals/3021/3021313900/H0313900.PDF)。
  通信制御の中身は書かれていないが、設定項目(パスワード6種、センター確認コード、テキスト連続送受信回数)が仕様の読みの裏付けになる。

## 5. フォーマット (第VII章)

**TTC (伝送テキストコントロール) 5バイト**: X(1)情報区分 + B(2)テキストシーケンス番号 + B(2)テキスト長(TTC込み)
- 並び順は仕様書74頁の図の矢印から読んだ(本文の説明は長さ→番号の順で書かれており、図と食い違う)。図の矢印は、この順でないと交差する。
- 情報区分は上位ニブルが接続形態(0=汎用機同士,1=汎用機-PC)、下位ニブルが電文区分(0=制御,1=データ)。
  日立のマニュアルがデータ電文の TTC 区分を '01'/'11' と書いており、この読みと合う。
- シーケンス番号: 制御電文は0、データ電文は1〜65535 (ファイル単位でリセット)。不連続なら切断。
- 1テキストは最大2048バイト。

**制御電文は固定64バイト。文字項目は EBCDIC。**

通信制御電文:

| 項目 | 型 | 値 |
|---|---|---|
| 電文区分 | X(1) | 00開局要求 01開局回答 02閉局要求 03閉局回答 04モード変更要求 05モード変更回答 |
| 処理結果 | X(1) | 00正常 10〜17,99 エラー(13=サービス時間帯、14=パスワード、17=モード変更不可) |
| 相手センター確認コード | X(7) | 10桁センターコード(電話番号右詰) + 4桁CPU/端末コード |
| 当方センター確認コード | X(7) | 同上 |
| 通信年月日時分秒 | X(6) | 年(下2桁)月日時分秒 |
| パスワード | 6B | 当事者間で決める |
| アプリケーションID | C(1) | 0=ファイル伝送 |
| モード | C(1) | 0=連絡 1=照会 |
| 拡張 | X(34) | 0x00 |

ファイル制御電文:

| 項目 | 型 | 値 |
|---|---|---|
| 電文区分 | X(1) | 10開始要求 11開始回答 12終了要求 13終了回答 14再送要求 |
| 処理結果 | X(1) | 00正常、10〜19,99 エラー(17=ファイルなし) |
| ファイル名 | 12B | 下記参照 |
| ファイルアクセスキー | 6B | 当事者間で決める |
| テキスト数 | B(2) | |
| レコード数 | B(3) | |
| レコードID | C(1) | 0=固定長 |
| レコード長 | B(2) | 総合振込なら120 |
| 再送指定区分 | B(4) | From(2) To(2) |
| データ圧縮ID | C(1) | 0/1 |
| ファイル名補助情報 | 17B | 任意。アクセスID(2)+補助(15) |
| 拡張 | X(14) | 0x00 |

- ファイル名(12B)は、産業別コード C(4)=`5020` + データコード C(4) + サイクル C(2) + 補助情報ID C(1) + ダミー C(1)=`0` で構成する。
  データコードは「区分2桁 + 種別2桁」の順。区分は 00=預金出入連絡、01=振込・振替依頼、02=融資、03=財形、04=外為。
  総合振込は `5020` `0121` `01` `0` `0` (区分01 + 種別21)、振込入金通知は `5020` `0001` ...。
  一覧は別冊 第I章5 (9頁)。(初版でこの順序を誤記していたため訂正)
- 文字コードは、制御電文が EBCDIC で、データ電文が EBCDIC、JIS8、シフトJIS のいずれか。
  どれを使うかは両者の取り決め。
- 圧縮(第X章)は任意で、ゼロ(0xF0)とスペース(0x40)の繰り返し圧縮。EBCDICデータが前提。
  使うかどうかはファイル単位で取り決める。

## 6. 別冊: 適用業務とレコード (`ref/jba_protocol_pc.pdf`、令和8年10月・13版、188ページ)

- 適用業務は32種類で、各業務に伝送モードが決まっている。
  - 連絡モード(依頼側が送る): 総合振込、給与・賞与振込、口座振替依頼、外国送金依頼など。
  - 照会モード(依頼側が受け取る): 振込入金通知、入出金取引明細、残高通知(預金)、各種処理結果明細など。
- ファイルは4種類のレコードで構成する。
  - ヘッダ(データ区分1) → データ(2) → トレーラ(8) → エンド(9) の順。
  - ヘッダは複数あってもよいが、種別コードは同一にする。
- レコード長は業務で決まっている。給与・総合振込などは **120**、振込入金通知・入出金取引明細・残高通知は **200**。
- 項目の型は N(数字)と C(文字)の2つ。N は右詰め・前ゼロ埋め、C は左詰め・後ろスペース埋め。
  ※印の任意項目は省略でき、省略時はスペース(ダミー項目も同様)。
- 文字コードはヘッダのコード区分で決まる(0=JIS、1=EBCDIC)。
  EBCDIC/JIS の使用文字表は付録1(175頁)。人名欄は半角カナ、英大文字、数字、`( ) - .`、スペースのみ(小文字カナ不可)。
  この種類は PDF 上の表が崩れていて自動抽出できないため、実装時に表を起こす必要がある。
- 預金種目コード: 1=普通 2=当座 3=納税準備 4=貯蓄 5=通知 6=定期 7=積立定期 8=定期積金 9=その他。

| トレーラ | データ区分N1=8 / 合計件数N6 / 合計金額N12 / ダミーC101 |

- 顧客コード1・2は、識別表示=`Y` のとき EDI 情報 C20(顧客コード1+2の20桁分)として扱う。
- 新規コード: 1=第1回振込分、2=変更分、0=その他。
- 振込指定区分: 7=テレ振込、8=文書振込。

| エンド | 9 / ダミーC199 |

- フォーマットB は金額が12桁に拡張されたもの(金額(2)N12を追加)。今回は不要と考える。
- 日付は和暦YYMMDD(令和の年)と書かれている。

### ファイル名補助情報 (任意、17B)

- アクセスID X(2) のビットで使用目的を表す: 0x8000=日付指定(3B)、0x4000=口座番号指定(9B)、0x2000=外為取引情報区分。
- 補助情報部分は左詰めで、残りは 0x00 埋め。
- ファイル制御電文のファイル名補助情報IDが1のときだけ使う。学習用途なら使わなくてよい。
